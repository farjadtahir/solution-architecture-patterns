# Security Policy

This repository contains documentation only. It has no runtime code, no services, and no stored secrets, so the usual software vulnerability reports rarely apply.

## What to report privately

Please report privately if you find any of the following:

* A leaked credential, token, or personal data in the repository or its history.
* A link in the docs that points to a malicious or compromised site.
* A problem in the GitHub Actions workflow that could expose secrets or allow untrusted code to run.

## How to report

Use GitHub private vulnerability reporting through the **Security** tab of this repository, if it is enabled. Otherwise email <farjad_tahir@splashpk.com>.

Please do not open a public issue for these cases.

## What to expect

We aim to acknowledge a report within seven days and to fix confirmed problems promptly. Because this is a volunteer documentation project, we cannot promise a fixed response time.

## Technical errors in the docs

A wrong or misleading statement about an architecture pattern is not a security issue. Please open a regular "Correction or bug" issue instead.
